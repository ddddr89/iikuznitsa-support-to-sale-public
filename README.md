# Support-to-Sale AI

Демо для хакатона «ИИКузница». Клиент ищет позиции и отправляет заявку. Менеджер формирует и скачивает коммерческое предложение. Контракты и график интеграции описаны в [архитектуре](docs/architecture.md).

## Локальный запуск

Нужны Python 3.12 и SQLite с поддержкой FTS5. Запускайте команды из корня репозитория.

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
export APP_DB_PATH=./demo.sqlite3
.venv/bin/python -m app.catalog "$APP_DB_PATH" data/demo.csv
read -rsp 'Токен менеджера: ' MANAGER_TOKEN
export MANAGER_TOKEN
.venv/bin/uvicorn app.main:app --host 127.0.0.1 --port 18080 --no-access-log
```

Клиент открывается на `http://127.0.0.1:18080/`, менеджер на `/manager`, документация API на `/docs`. Для подключения к VPS пробросьте порт через SSH. Менеджер вводит тот же токен в кабинете. Без токена кабинет возвращает 503. HTML-файл КП можно распечатать в PDF средствами браузера.

По умолчанию чат отвечает на основе каталога. Для подключения моделей см. [инструкцию n8n](n8n/README.md). Заявки с контактами хранятся локально, поле чата предназначено для вопросов о товарах.

## Загрузка Softline

Получите полный экспорт у владельца каталога и преобразуйте его в UTF-8 CSV по заголовку [демо-файла](data/demo.csv). SKU должен быть уникальным и содержать до 200 символов. Цена указывается целым числом в копейках, пустое значение означает «цена по запросу». Укажите RUB и пустой либо HTTP(S) URL. Используйте ту же команду импорта с путём к выгрузке и нужной БД. Импорт целиком заменяет снимок каталога и выводит число загруженных SKU. Сверьте его с источником и проверьте контрольные артикулы.

## Проверка

Из корня запустите `bash tests/run-smoke.sh`. Сценарий использует временную БД, тестовый токен и отдельный процесс на localhost. Для занятого порта задайте `SMOKE_PORT`. Проверяются страницы, OpenAPI, поиск, каталожный чат, заявки, доступ менеджера, расчёт и скачивание КП, обработка неизвестного SKU и цены по запросу.

## Конкурсный HTTPS-стенд

`bash deploy/start-stand.sh` запускает отдельную сессию tmux на
`https://localhost:18443` с сертификатом проекта и отдельной SQLite. При первом запуске она получает
выборку из шести карточек Softline из `data/softline-sample.csv`.
Процесс читает настройки провайдеров из
`/home/demon/.config/iikuznitsa/secrets.env`. Локальный токен менеджера
хранится в `.stand/manager-token`. Каталог `.stand/` исключён из Git.

Для доступа с другой машины пробросьте
`ssh -L 18443:127.0.0.1:18443 <пользователь>@<VPS>`. Откройте
`https://localhost:18443/` или `https://localhost:18443/manager`.
Для проверки curl используйте копию публичного `.stand/cert.pem` и
`--cacert`. Сертификат самоподписанный. Публичная ссылка с доверенным
HTTPS потребует DNS-имени и сертификата для него.

Для остановки используйте
`tmux -S "$PWD/.stand/tmux.sock" kill-session -t support-to-sale`.
После обновления кода остановите процесс и повторите команду запуска.

В кабинете менеджера можно скачать PDF КП и проект счёта. Проект счёта
требует проверки реквизитов перед выставлением. Одинаковые заявки за
10 минут объединяются, а запрос на эскалацию поднимает заявку в начало
очереди. Идентичный набор позиций и цен для заявки возвращает существующее КП.
`bash tests/run-smoke.sh` дополнительно запускает 15 конкурсных тестов.

### Обновление снимка

Для YML с официальным числом позиций используйте команду
`.venv/bin/python -m app.catalog_feed .stand/catalog.sqlite3 --file /путь/к/выгрузке.yml --expected-count N`.
Для загрузки по HTTPS передайте URL через `SOFTLINE_FEED_URL` и опустите
`--file`. Для CSV используйте `app.catalog` с `--source softline_feed --expected-count N`.
При ошибке или несовпадении количества SQLite сохраняет предыдущий снимок.
Актуальный источник и число SKU видны в клиентском интерфейсе и в
`/api/v1/catalog/status`.
