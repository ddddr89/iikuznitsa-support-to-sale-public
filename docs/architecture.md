# Support-to-Sale AI

FastAPI обслуживает два интерфейса и владеет SQLite. Каталог загружается отдельной CLI-командой из нормализованного CSV, поиск использует SQLite FTS5. Chat API подбирает товары и передаёт модели только текст запроса и найденные карточки. n8n оркестрирует YandexGPT → GPT-5.4 mini, FastAPI при недоступности webhook возвращает каталожный ответ. SQLite хранит заявки и неизменяемые позиции коммерческих предложений. Менеджер вручную формирует и скачивает КП. Браузеры обращаются к FastAPI по тому же origin.

## Контракт HTTP /api/v1

- GET /health — состояние процесса, без обращения к провайдерам.
- GET /products?q=&limit=20&offset=0 → {items: Product[]}. limit 1–100. Product = {sku, name, category, description, url, price_minor, currency}. price_minor — целое число в минимальных единицах валюты либо null. Валюта — RUB.
- POST /chat {message} → {answer, products: Product[], provider}. provider: yandex, openai или catalog. Запрос 1–2000 символов. Товары в ответе определяет сервер.
- POST /leads {contact, message, sku?} → 201 {id, contact, message, sku, created_at}. Заявка передаётся менеджеру без отправки внешним адресатам.
- GET /manager/leads → {items: Lead[]}, последние 100. Доступ через Authorization: Bearer <MANAGER_TOKEN>.
- POST /manager/quotes {lead_id, items: [{sku, quantity}]} → 201 {id, total_minor, currency, download_url}. Тот же доступ. Количество 1–999, 1–50 позиций. Цена и наименование фиксируются при создании.
- GET /manager/quotes/{id}/download → text/html; attachment. Доступ менеджера. КП содержит позиции, количества, цены, суммы и итог.
- Ошибки через detail: 401 неверный токен, 404 неизвестный объект, 409 цена по запросу, 422 нарушение схемы, 503 выключенный кабинет.

## Внутренние контракты Python

- app.catalog.Catalog(db_path) имеет init(), search(q, limit=20, offset=0) -> list[dict], get(sku) -> dict | None. CLI python -m app.catalog DB CSV. CSV содержит те же столбцы, что Product. Импорт заменяет снимок целиком атомарно. Пустая цена обозначает цену по запросу.
- app.ai.reply(message, products) -> dict с answer и provider. Приложение добавляет products. При настроенном N8N_WEBHOOK_URL отправляет POST {message, products} с X-Webhook-Secret из N8N_WEBHOOK_SECRET. Webhook отвечает {answer, provider}. Схема данных одинакова для локального тестирования и боевого шлюза.
- app.commercial.Commercial(db_path) имеет init(), create_lead(contact, message, sku), list_leads(), create_quote(lead_id, items) и download_quote(quote_id) -> str. create_quote получает позиции на входе с полями sku, name, quantity, price_minor и возвращает id, total_minor, currency. Методы возвращают словари или списки словарей. Отсутствующая заявка или КП вызывает KeyError.
- app/static/index.html и manager.html доступны на / и /manager. Общие ресурсы на /static/.

## Четыре блока и интеграция за 48 часов

| Часы | Работа и критерий готовности |
|---|---|
| 0–4 | Контракты, диагностика, образец CSV и разделение файлов. |
| 4–18 | Параллельно: каталог и FTS, шлюз ИИ и workflow n8n, клиентский и менеджерский интерфейсы, SQLite для заявок и КП с проверками. Каждый блок проверяется на фикстурах. |
| 18–30 | Каталог → API выдачи → chat с заглушкой → экраны → заявки и скачивание КП. Проверяем отказы, сумму и права доступа. |
| 30–42 | Получаем полный экспорт Softline, сверяем число SKU, проверяем поиск на реальной выборке. Подключаем n8n и последовательно проверяем YandexGPT, OpenAI и деградацию. |
| 42–48 | Репетиция демо, повтор сквозных проверок, заморозка версии. |

Полнота каталога подтверждается сверкой с предоставленным снимком Softline. Для разработки используем демонстрационный CSV. Контакты остаются в SQLite. Для демо сервер слушает localhost, доступ извне организуется через SSH-туннель. Перед внешней публикацией нужны HTTPS, ограничение частоты запросов и отдельная аутентификация менеджеров.

## Среда и рабочие области

Проверены Ubuntu 24.04.4 LTS, Python 3.12.3, Git 2.43.0, Docker 29.1.3, Compose 2.40.3 и Codex CLI 0.172.0. Docker CLI не имеет доступа к сокету. Проверка `http://127.0.0.1:5678/healthz` на хосте вернула 200.

CLI показывает включённый флаг `multi_agent`. Три подагента успешно выполнили задачи параллельно в текущей сессии. В репозитории пока нет первого коммита, поэтому для разработки использованы четыре каталога `/tmp/support-to-sale-{catalog,ai,ui,commercial}`. Результаты собраны в рабочей папке. После первого коммита эти блоки можно вести в Git worktree.

Сквозная проверка на временном сервере прошла с шестью демонстрационными SKU. На действующий n8n проверка отправляла только запрос состояния.

## Расширения конкурсной версии

- Chat возвращает `actions: [{type, status}]` для фактически выполненных операций. YandexGPT может вызвать поисковый инструмент, который читает каталог через тот же слой SQLite. Провайдер и действие в интерфейсе берутся из ответа API.
- Lead принимает необязательное `escalation`. Ответ включает `status` и `duplicate`. В очереди менеджера эскалированные заявки идут первыми.
- Quote возвращает `quote_pdf_url` и `invoice_pdf_url` вида `/api/v1/manager/quotes/{id}/{kind}.pdf`. Требуется Bearer-токен. HTML-скачивание остаётся доступным по исходному URL.
- HTTPS-стенд работает отдельным процессом на интерфейсе loopback. Параметры запуска и доступ через SSH описаны в README.
- `GET /api/v1/catalog/status` возвращает `source`, `item_count` и `imported_at`. Источник отражает последний успешно загруженный снимок. Клиент показывает, если в SQLite демо-данные либо выборка Softline.

### Подтверждение ответа менеджером

`PUT /api/v1/manager/leads/{lead_id}/knowledge` принимает
`{question, answer, anonymized: true}` с Bearer-токеном менеджера. В базу знаний
попадает отредактированная пара вопрос–ответ. Контакты и исходное обращение
автоматически не переносятся. Повторное подтверждение заменяет запись для
этой заявки. Обновление справочных материалов сохраняет записи менеджера.
Точное совпадение вопроса возвращает проверенный текст из SQLite через
`provider: knowledge`. Для близких формулировок подходящая запись
добавляется в контекст модели.
