# Архитектура Support-to-Sale AI

## Компоненты

| Компонент | Что делает |
| --- | --- |
| Nginx и FastAPI | Обслуживают клиентский чат и кабинет менеджера на одном HTTPS-домене. FastAPI проверяет входные данные и права, выбирает маршрут ответа, возвращает карточки и фактические действия. |
| SQLite и FTS5 | Хранят каталог, индекс базы знаний, заявки, историю и документы. Каталог обновляется отдельной CLI-командой с атомарной заменой снимка. Справочные материалы могут храниться в отдельной SQLite. |
| n8n и YandexGPT Pro 5.1 | Принимают запросы, которым нужна модель. Модель может запросить один поиск в каталоге. Состояние заявки, цены и выпуск документов остаются в прикладном коде. |
| ReportLab и интерфейс менеджера | Формируют КП и проект счёта на основе одного сохранённого набора строк. Документы выпускаются действием менеджера. |

## Маршрут чата

1. FastAPI извлекает подтверждённый ответ, ограничения подбора и кандидатов каталога. Для части запросов применяются предметные правила и формируется локальный ответ. Для консультации с моделью FastAPI отправляет сообщение, историю, выдержки из знаний и до пяти предварительно найденных карточек.
2. Локальный Nginx ingress проверяет Basic Auth и отбрасывает заголовки исходного запроса. n8n собирает запрос к YandexGPT. Если модель вызвала `search_catalog`, workflow проверяет строку запроса, получает до пяти карточек из `GET /api/v1/products` и запрашивает итоговый ответ.
3. FastAPI проверяет ответ вебхука, сверяет артикулы итоговых карточек с SQLite и возвращает клиенту сведения о маршруте в `actions`. Уточнения условий, отсутствие проверяемой позиции или просьба позвать менеджера обрабатываются приложением.
4. При сбое вебхука FastAPI пробует прямой YandexGPT, если настроены его учётные данные. Если модель недоступна, клиент получает каталожный ответ. Обращение владельца с действующей сессией может перейти в очередь менеджера. Узел GigaChat оставлен в экспорте как отключённое направление развития.

Контакты из формы заявки хранятся отдельно. Свободный текст, который клиент самостоятельно вводит в чат, может передаваться модели. Сохранение подробностей успешных и ошибочных исполнений n8n отключено. [Настройка n8n](../n8n/README.md) · [Проверка безопасности n8n](n8n-security-audit.md)

## API

Пути указаны относительно `/api/v1`. Полная схема доступна в `/docs` на запущенном экземпляре.

| Маршрут | Назначение и основные поля |
| --- | --- |
| `GET /health` | Готовность процесса принимать HTTP. Узел не выполняет внешние запросы. |
| `GET /catalog/status` | Источник, количество позиций и дата успешного импорта. |
| `GET /products?q=&limit=20&offset=0` | Возвращает `items` со SKU, описанием, категорией, ссылкой и `price_minor` в копейках. `null` означает цену по запросу. |
| `POST /chat` | Принимает `message` и необязательную `history`. Возвращает `answer`, `products`, `provider`, `actions`, `sources` и, если применимо, `escalation`. |
| `POST /leads` | Принимает `contact`, `message`, необязательные `sku` и `escalation`. Возвращает идентификатор, статус и признак повтора. В публичном профиле требует действующую cookie-сессию. |
| `GET /client/leads`, `GET /client/chat-history`, `GET /client/manager-messages` | Открывают или используют браузерную сессию для списка заявок, истории и ответов менеджера. Клиент видит свои обращения. |
| `GET /client/leads/{id}`, `GET /client/quotes/{id}/{kind}.pdf` | Детали заявки и PDF доступны владельцу активной сессии. |
| `GET /manager/leads`, `PATCH /manager/leads/{id}` | Список до 100 заявок и смена статуса либо ответ. Эскалации идут первыми. Кабинет требует Bearer-токен. |
| `POST /manager/quotes` | Принимает `lead_id` и пары `sku`/`quantity`, берёт цены из каталога и формирует оба PDF. Возвращает идентификатор, сумму и ссылки для скачивания. При отсутствии цены возвращает 409. |
| `PUT /manager/leads/{id}/knowledge` | Сохраняет отредактированную пару вопрос–ответ с `anonymized: true`. Точное совпадение вопроса может обслуживаться напрямую из базы знаний. |

Клиентская сессия живёт семь дней. Cookie имеет атрибуты `Secure`, `HttpOnly` и `SameSite=strict`. Ответ менеджера доставляется в открытый чат при очередном запросе к API. В публичном профиле `APP_REQUIRE_LEAD_SESSION=1` общий лимит создания заявок для ручного и автоматического маршрута составляет до 5 попыток на владельца и до 30 на процесс за 60 секунд. Без действующей сессии чат не ставит вопрос в очередь автоматически. Для локального запуска по умолчанию сохранён прежний контракт ручного `POST /leads`. Проект счёта предназначен для проверки менеджером. [Код API](../app/main.py) · [Сессии и документы](../app/commercial.py)

## Проверки

Локальная HTTP-регрессия использует временную SQLite и синтетический каталог. Модульные тесты шлюза подменяют внешние ответы и проверяют контракт, лимит инструмента и запасной маршрут. Публичный аудит дополняет эти проверки реальными ответами на клиентские запросы. [Команды запуска и тестов](../README.md) · [Аудит 100 сценариев](audit-100.md)
