# Материалы для конкурсной формы

Кейс «Агент поддержки», трек «Клиентские сценарии». Ниже приведены ответы
по составу подачи из п. 4.5 положения. Названия дополнительных полей и
ограничения длины формы сверяются в личном кабинете. Для оценки учитывается версия, поданная до окончания спринта (п. 4.6). [Положение конкурса](https://иикузница.рф/regulations/v1.html)

## Название и краткое описание

**Support-to-Sale AI.** ИИ-помощник для выбора товаров Softline и передачи
предметных обращений менеджеру. Он ищет позиции в полном снимке каталога,
уточняет потребность, отвечает по базе знаний и помогает оформить заявку.
Менеджер получает контекст, формирует КП, отправляет ответ и может сохранить
обезличенную формулировку для следующих обращений.

## Проблема и пользователи

Покупателю нужна консультация при поиске конкретного продукта или выборе
решения без готового артикула. Задача прототипа — ответить на типовые вопросы,
собрать требования и сократить объём сведений, который приходится запрашивать
менеджеру повторно. В кейсе указана нагрузка около 500 обращений в день.
Фактическое сокращение времени менеджера и влияние на продажи требуют
пилотного замера.

## 1. Что сделано за 48 часов и что нет

### Реализовано

- Подбор по известному товару и по описанию потребности, уточняющие вопросы,
  ответы по каталогу и базе знаний, история чата.
- Поиск по 136 040 товарным предложениям из выгрузки. Поиск по артикулу,
  коду производителя и описанию. Вызов поиска из YandexGPT.
- Передача обращения менеджеру, статусы и ответы, история и документы
  в клиентской сессии. Приоритетное обращение видно менеджеру первым, ответ приходит в существующий клиентский чат. Подтверждённый обезличенный ответ используется при следующем запросе.
- Формирование PDF коммерческого предложения и проекта счёта. Заявка и
  документы доступны владельцу сессии. Пара PDF создаётся атомарно. Итог считается из каталожных цен. Кабинет менеджера защищён токеном.

### В планах

Сквозная оплата и подтверждение покупки, получение актуальных складских
остатков из учётной системы, восстановление заявки после истечения
семидневной браузерной сессии, ответ клиента в ветке конкретной заявки и
автоматическое проведение согласованного заказа. GigaChat обозначен как запланированная резервная модель n8n. Ветка отключена, учётные данные отсутствуют. Прямой маршрут к YandexGPT через FastAPI
работает независимо от n8n. Проект счёта требует проверки реквизитов менеджером перед выставлением. Совместимость сложных лицензий и наличие товаров требуют отдельного подтверждения.

## 2. Подход и архитектура

Клиентский интерфейс обращается к FastAPI. Для обычного вопроса FastAPI
получает релевантный контекст из SQLite и передаёт его в n8n. YandexGPT Pro 5.1
формирует ответ. По необходимости он запрашивает поиск по каталогу и
достраивает ответ с полученными карточками. Для точного совпадения с
подтверждённым ответом FastAPI использует базу знаний. При сбое n8n доступен
прямой вызов YandexGPT. При недоступной модели приложение даёт каталожный ответ и сохраняет обращение в очереди менеджера. Точные запросы и ограничения могут обрабатываться без вызова модели. Обращения, права доступа и документы обслуживает приложение.

## 3. Стек и модели

Python 3.12, FastAPI, SQLite/FTS5, n8n, YandexGPT Pro 5.1 через Responses API,
HTML/CSS/JavaScript, ReportLab, Playwright, Nginx и systemd. Данные
задачи — выгрузка каталога Softline, справочные страницы, тематическая
статистика из обезличенных переписок и шаблон КП. Исходные переписки
и файлы материалов хранятся вне Git.

## 4. Расчёт стоимости эксплуатации

Измерен полный подбор товара через n8n и YandexGPT Pro 5.1. Первый вызов
использовал 216 входящих и 18 исходящих токенов, второй после поиска —
319 входящих и 48 исходящих. Итог опубликованного XLSX по формулам
составляет **0,39410 ₽ за обращение без НДС**. Расходы VPS, эксплуатации,
поддержки и времени менеджера в эту сумму не входят. [Данные и формула](economics.md)

## 5. Запуск и поставка

Исходники приложения, workflow без учётных данных, инструкции запуска,
демо-данные и тесты. Локальный запуск с каталожным ответом выполняется по
[README](../README.md). Для модельного режима нужны настройки n8n и
учётные данные Yandex AI Studio. Полный импорт требует доступа к
материалам заказчика. Откройте `/manager` и получите тестовый доступ у
владельца стенда по защищённому каналу. В локальной автоматизированной демонстрации
используется отдельная SQLite с тестовым доступом.

Пример запроса к действующему каталогу — `GET /api/v1/products?q=U2424H`.
Ожидаемый ответ содержит `items` с монитором Dell U2424H и SKU `465223`.
Точный чат-запрос может дать каталожный ответ без вызова модели. Для демонстрации двух вызовов модели используйте сценарий с инструментальным поиском, подтверждённый трассой. Публичный прогон 100 новых сценариев дал 75 PASS, 21 PARTIAL и 4 FAIL. После исправлений отдельно перепроверены 14 затронутых сценариев, все PASS. [Полный аудит](audit-100.md)
