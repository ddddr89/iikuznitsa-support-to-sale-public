# Приоритетные обращения и пакет документов

Проверено 27 ноября 2026 года на публичном HTTPS-стенде. Автоматическая передача открывает приоритетное обращение для активной клиентской сессии по прямой просьбе об операторе или когда по ответу нельзя подтвердить нужный результат. Уточняющие вопросы сами по себе заявку не создают. Действующий статус API `escalated` отображается как «Ожидает ответа менеджера». Очередь сортирует такие обращения первыми, отдельный счётчик включает и записи за пределами первых 100.

Ответ менеджера и новый статус записываются в одной транзакции. В обычном случае статус меняется на «Ответ отправлен»; явное закрытие сохраняется. Клиентский чат подгружает ответы раз в 8 секунд в видимой вкладке. При возвращении во вкладку запускается внеочередное обновление. Ответы восстанавливаются из истории сессии после перезагрузки. Клиентский API читает ответы только по владельцу активной cookie-сессии и возвращает `Cache-Control: no-store`. [Код](../app/main.py) · [Хранение](../app/commercial.py)

Кнопка «Подготовить документы» использует один сохранённый набор позиций и формирует оба PDF в одной транзакции. Ошибка любого рендера откатывает пакет. Повтор идентичного запроса возвращает уже созданный пакет. Старые документы продолжают скачиваться по своим адресам. В чате для карточек с ценой есть «Запросить документы»; запрос создаёт обычную заявку, документы выпускает менеджер. Скачиваются два отдельных файла. Проект счёта явно не предназначен для оплаты. Подтверждённых реквизитов продавца, покупателя и налоговых данных для юридически завершённого счёта в проверенном сценарии нет, поэтому выставление передано менеджеру. [Генератор PDF](../app/documents.py)
