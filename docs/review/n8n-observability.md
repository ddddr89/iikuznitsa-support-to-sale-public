# Проверка наблюдаемости n8n и YandexGPT

27 ноября 2026 года опубликована минимальная доработка существующего активного workflow `Support-to-Sale AI | Chat v1`, ID `iikuznitsaChat01`. Версия `9c8a214a-71a6-49dc-90cd-4fe69e68ba05`. Изменена отправляемая служебная телеметрия узла разбора ответа. Модель, подключения, граф маршрута, учётные ссылки и настройки хранения сохранены.

## Живые проверки

Синтетический запрос через публичный чат сопоставлен по внутренней тестовой метке с метаданными n8n. **Исполнение №208**, 13:28:46.011–13:28:47.018 UTC, статус `success`, режим `webhook`. От публичного POST до ответа с HTTP 200 прошло **1,078 с**. FastAPI зафиксировал `route_n8n`, `tool_catalog_search` и `model_yandex` со статусом `done`. Результат — Dell U2424H, артикул **465223**, каталог **26 173 ₽**.

| HTTP-узел YandexGPT Pro 5.1 | Вход | Выход | Сумма |
| --- | ---: | ---: | ---: |
| Запрос к Яндексу | 722 | 18 | 740 |
| Яндекс после поиска | 825 | 21 | 846 |
| **Итого** | **1 547** | **39** | **1 586** |

Последовательность подтверждается счётчиками ответов двух HTTP-узлов, успешной веткой инструмента и опубликованным графом. Рабочий путь — «Приём обращения» → «Подготовка запроса» → «Запрос к Яндексу» → «Разбор вызова поиска» → «Нужен поиск?» → «Поиск в каталоге» → «Яндекс после поиска» → «Разбор ответа Яндекса» → «Проверка ответа» → «Отправка ответа». Полная покадровая трасса узлов не сохранялась. Расчёт за 1 586 токенов по стандартным ставкам входа и выхода составляет **1,04000 ₽ без НДС**. Это оценка, а не счёт из биллинга. [Тариф](https://aistudio.yandex.ru/ru/docs/ai-studio/pricing)

Прямой YandexGPT проверен отдельным процессом без отключения рабочего n8n. Один вызов за 856 мс дал 192 входящих и 45 исходящих, 237 токенов и оценку 0,15540984 ₽ без НДС. Никаких выводов о распределении органических запросов из этой проверки не делается.

Надёжной исторической разбивки реального клиентского трафика по n8n, прямому маршруту и локальной обработке нет. Сохранившиеся записи вебхука выборочны и не отделяют тесты от реальных клиентов. До обновления usage n8n обычно описывал только последний ответ модели. Точный товарный запрос с ограничениями, подтверждённая база знаний и часть справочных правил FastAPI отвечают локально. Прямой YandexGPT используется при отсутствии или отказе шлюза. В контрольном точном запросе до обновления получен `provider: catalog` без `route_n8n`, отдельно от исполнения №207 через n8n.

## Сохранение и журнал

В опубликованной версии `saveDataSuccessExecution=none`, `saveDataErrorExecution=none`, `saveManualExecutions=false`, `saveExecutionProgress=false`. В PostgreSQL для контрольного №207 проверено: контейнер `runData` не содержит сохранённых узлов. Метаданные короткого окна не равны полной истории Executions. В интерфейсе настройки видны через **Workflow → ⋯ → Settings**. Сохранение полных данных для диагностики не включалось.

Обезличенные JSON-строки `model_execution` хранятся в защищённом ротируемом журнале `.stand/model-usage.log`. Каждая попытка маршрута имеет случайный `request_id`; резервные попытки разделяют его, но пишутся отдельными строками. Сумма берётся из массива вызовов, устаревшее поле с последним счётчиком при наличии массива не прибавляется. Для сбоя с недоступными данными n8n полный расход неизвестен, запись выделена `partial: true`. Журнал содержит только технические поля, без сообщений, контактов, IP и заголовков. Итоговая оценка тарифа вычисляется для полного набора счётчиков Pro 5.1 и не подтверждает списание средств.

Модульная регрессия — 61 тест. Конкурсная — 16 тестов и smoke API. Отдельные тесты проверяют два счётчика, отсутствие двойного прибавления устаревшего usage, неполный сбой с прямым резервом и отсутствие текстов в журнале. Видео и форма не изменены.
