# Support-to-Sale AI · тексты для конкурсной формы

**Кейс:** «Агент поддержки». **Трек:** «Клиентские сценарии». Порядок полей соответствует п. 4.5. В официальном положении спринт и подача завершаются 28 ноября 2026 года в 10:00 МСК. Для оценки учитывается версия, отправленная до окончания спринта. [Положение конкурса, пп. 2.4.2, 4.5, 4.6, 4.8](https://иикузница.рф/regulations/v1.html)

## Название и краткое описание

**Support-to-Sale AI.** ИИ-помощник для покупателей интернет-магазина Softline. Находит товар по названию или артикулу, подбирает варианты по описанию задачи, отвечает по базе знаний и передаёт вопросы менеджеру с контекстом. Менеджер может ответить в чате клиента и подготовить коммерческое предложение и проект счёта.

## 1. Что реализовано за спринт

В прототипе работают два клиентских сценария. Если покупатель знает модель, помощник находит карточку по названию, артикулу или коду производителя. Если покупатель описывает потребность, помощник уточняет требования и подбирает позиции по характеристикам и бюджету. Обе ветки работают со снимком из 136 040 товарных предложений Softline. В консультации с YandexGPT модель может вызвать поиск по каталогу через n8n.

Клиент может передать вопрос менеджеру и проверить состояние обращения в разделе «Мои заявки». Менеджер видит контекст, меняет статус, отвечает в исходный чат и может вручную сохранить обезличенный ответ в базе знаний. Заявка остаётся выше обычных заявок, пока требует ответа. По запросу КП или счёта чат сверяет артикул, количество и цену в снимке и автоматически готовит оба PDF. Ссылки появляются в диалоге, ZIP остаётся в «Моих заявках». Ручное формирование менеджером также доступно.

После явного завершения диалога по поддерживаемым темам система может извлечь канонический вопрос и дословно подтверждённый фрагмент источника Softline. В общую базу попадает только канонический текст, ссылка, дата и метод проверки. Для первого выпуска поддержаны статус заказа и переход к оформлению из корзины. Источник повторно проверяется при выдаче, дубли и расхождения с ручными записями блокируются.

На публичном стенде пройдено 100 сценариев в Chrome. Исходно 96 PASS, 2 PARTIAL и 2 FAIL. После целевых исправлений и перепроверок — **99 PASS, 1 PARTIAL, 0 FAIL**. В основных 100 сценариях было 67 тестовых заявок и 66 отправленных ответов менеджера. 23 сценария прошли через n8n/YandexGPT, 77 обработал FastAPI локально. Сверены 13 ZIP-пакетов с двумя PDF. Отдельно воспроизведена и исправлена причина PARTIAL: сопоставление названия HDD пропускало карточку при записи «на 2 ТБ» вместо «2TB». После публикации повторный браузерный запрос вернул карточку. Историческая оценка серии сохранена. Приёмочные сценарии использовали синтетические обращения и не измеряли конверсию продаж.

## Что реализовано частично и что осталось за пределами прототипа

Для лицензионных запросов, распознанных по семейству или явной формулировке, помощник уточняет количество пользователей или устройств, новую лицензию либо продление, срок и неоднозначную редакцию. Карточку показывает после сверки параметров с фидом. На стенде проверены MDaemon Standard, Dr.Web Gateway Security Suite, WinRAR, Radmin, CommuniGate Pro и Microsoft 365 Business Standard. При недостаточности сведений вопрос передаётся менеджеру без неподтверждённых карточек.

Ассортимент и цены берутся из импортированного снимка. Наличие, сроки поставки, цена по запросу и неоднозначные условия лицензирования требуют проверки менеджером. Проект счёта предназначен для согласования реквизитов. Заказы с оплатой, подтверждением покупки, автоматическим выставлением окончательного счёта и синхронизация складских остатков с учётной системой остались за пределами прототипа. Проведение сделок через CRM и автоматизация дальнейших операций не внедрены. Восстановление доступа при потере cookie или после истечения семидневной сессии не реализовано. Ветка GigaChat отключена. Прямой резерв через YandexGPT доступен при настройке соответствующих учётных данных.

Для ежедневного обновления каталога подготовлены HTTPS-импорт и расписание systemd. Успешная синхронизация с сервером Softline пока не подтверждена: передан локальный снимок, действующий HTTPS-адрес поставщика не найден. [Статус подключения источника](softline-catalog.md#ежедневная-синхронизация)

## 2. Подход, архитектура и принцип работы

1. Веб-клиент отправляет сообщение в FastAPI. Приложение проверяет сессию, применяет лимиты запросов и ищет подтверждённые ответы и позиции в SQLite.
2. Для точного правила подбора или подтверждённого ответа базы знаний FastAPI отвечает локально. Для консультации с моделью FastAPI передаёт вопрос и ограниченный контекст в n8n.
3. YandexGPT Pro 5.1 формирует вариант ответа либо запрашивает инструмент поиска. n8n вызывает API каталога и передаёт найденные карточки в следующий вызов модели. FastAPI сверяет карточки со снимком. Свободный текст модели проходит сверку с релевантной официальной выдержкой. В остальных случаях ответ собирается из проверяемых полей карточек либо предлагает уточнение или менеджера. Служебный журнал фиксирует маршрут, действия и число источников.
4. Если n8n недоступен, FastAPI может вызвать модель напрямую. При недоступности модели остаются каталог и обработка обращения менеджером. Заявки, права доступа и PDF обслуживает FastAPI.
5. Кабинет менеджера защищён токеном. Чужие обращения и документы недоступны клиентской сессии. Служебная телеметрия модели содержит маршрут, время и счётчики токенов. Полные исполнения n8n с текстами и авторизационными заголовками не сохраняются.

## 3. Стек, модели и инструменты

Python 3.12, FastAPI, Uvicorn, SQLite с FTS5, n8n, YandexGPT Pro 5.1 через Responses API, HTML/CSS/JavaScript, ReportLab, Nginx и systemd. Для проверки использованы модульные и HTTP-тесты и Playwright с Google Chrome. Модельный инструмент обращается к локальному индексу каталога через API.

## 4. Стоимость эксплуатации

Измерены два отдельных обращения с двумя вызовами YandexGPT Pro 5.1 через n8n и поиском по каталогу между вызовами. В официальном XLSX рассчитан первый случай. Второй замер приведён отдельно.

| Замер | Первый вызов, вход / выход | Второй вызов, вход / выход | Всего токенов | Расчёт без НДС |
| --- | ---: | ---: | ---: | ---: |
| Сценарий официального XLSX | 216 / 18 | 319 / 48 | 601 | 0,39410 ₽ |
| Контрольный сценарий с инструментом | 722 / 18 | 825 / 21 | 1 586 | 1,04000 ₽ |

Суммы рассчитаны по токенам и ставке, использованной в конкурсном калькуляторе. Это два наблюдения стоимости модели, по которым нельзя вывести среднюю стоимость 100 обращений или подтвердить фактические начисления биллинга. Локальные ответы FastAPI обходятся без вызова модели. VPS, сопровождение и время менеджера учитываются отдельно. Подтверждённой доли общих расходов VPS и биллинговой сверки по проекту нет. Если выделенная доля VPS стоит V ₽ в месяц, при N обращениях инфраструктурная доля составляет V/N ₽ на обращение без учёта труда.

[Скачать официальный калькулятор XLSX](https://github.com/ddddr89/iikuznitsa-support-to-sale-public/releases/download/submission-2026/iikuznitsa-calculator.xlsx) · [Методика расчёта](economics.md) · [Тариф Yandex AI Studio](https://aistudio.yandex.ru/ru/docs/ai-studio/pricing)

**Начисления в период спринта.** По показаниям интерфейса AI Studio, переданным участником, 26 ноября показано 56,48 ₽, 27 ноября — 45,02 ₽, общий итог на экране — 101,51 ₽. Дневные строки суммируются в 101,50 ₽. Суммы приводятся как показания за период разработки и испытаний. Принадлежность всех начислений проекту, состав продуктов и НДС по аккаунту требуют экспорта детализации. Для резидента РФ стандартная детализация в рублях включает НДС. Эти суммы не используются для расчёта средней стоимости эксплуатации. [Ограничения сверки](economics.md#начисления-за-период-разработки-и-испытаний)

### Разовая стоимость внедрения пилота

Сценарный прогноз для отдельного чата на готовом стенде с одной группой менеджеров, одним согласованным товарным фидом, предоставленной базой знаний и действующим доступом к Yandex AI Studio. Работы: согласование процесса и доступов — 8–12 ч, подключение и проверка данных — 12–20 ч, настройка окружения и базового мониторинга — 8–12 ч, приёмка обоих клиентских сценариев и передачи менеджеру — 12–20 ч, обучение и передача инструкций — 4–8 ч. Итого **44–72 человеко-часа**. При условной ставке **2 500 ₽/час** бюджет работ составит **110 000–180 000 ₽**. Ставка и часы — допущения для обсуждения, подтверждённых расходов или предложения подрядчика нет. Налоги, лицензии, VPS, модельные вызовы, сопровождение и работа менеджеров в расчёт внедрения не включены. Интеграцию с боевой витриной, CRM, оплатой или системой остатков нужно оценивать отдельно при запросе партнёра. Эффект пилота оценивается по доле подтверждённых ответов, времени менеджера на обращение и частоте передачи человеку.

## 5. Запуск, поставка и пример работы

В публичной поставке есть исходный код, клиентский и менеджерский интерфейсы, очищенный экспорт n8n, демонстрационный CSV, тесты и инструкции. Локальный режим поднимается по README из Python 3.12 с демонстрационным каталогом. Для PDF нужен шрифт DejaVu Sans. Для режима с моделью импортируйте экспорт в свой n8n, настройте адрес API каталога и доступ Yandex AI Studio вне репозитория. Полный импорт требует предоставленных материалов кейса.

Дополнительная регрессия очереди на отдельной базе проверила создание 120 уникальных заявок, все пять страниц кабинета, глобальный счётчик, сохранение приоритета до ответа и отказ без авторизации. Прошли 69 модульных и 16 конкурсных тестов, а также smoke-проверка API. На публичном стенде проверены вход, вторая страница и фильтр обращений, требующих ответа.

На публичном стенде можно открыть чат и спросить «Есть ли в каталоге Dell U2424H?». Ожидаемый результат — карточка Dell U2424H с артикулом 465223, каталожной ценой при её наличии в снимке и без обещания складского остатка. Машиночитаемый пример — запрос `GET /api/v1/products?q=U2424H`, где в массиве `items` ожидается позиция с `sku: "465223"` и названием модели. Каталожный маршрут может ответить без вызова модели.

Для проверки работы менеджера откройте страницу «Я менеджер». Доступ выдаёт владелец стенда по защищённому каналу. Для независимого локального запуска проверяющий задаёт собственный токен и использует демонстрационную БД.

Первые коммиты проектного кода датированы официальным окном спринта. В разработке использованы FastAPI и Pydantic (MIT), Uvicorn (BSD-3-Clause), ReportLab (BSD), Playwright (Apache-2.0), SQLite (общественное достояние), Montserrat (SIL Open Font License 1.1) и DejaVu Sans для PDF. n8n используется на условиях Sustainable Use License, YandexGPT Pro 5.1 — по условиям Yandex AI Studio. В стенде использованы выгрузка Softline, справочные материалы и тематические сведения из обезличенных примеров. Генератор КП может использовать фирменные элементы локального PDF-образца оформления.
