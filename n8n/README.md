# Шлюз ИИ в n8n

1. Рабочий workflow `Support-to-Sale AI | Chat v1` имеет ID `iikuznitsaChat01`. Обновляйте существующий workflow по этому ID. Доступ проверяет локальный шлюз через Basic Auth. Перед передачей в узел **Приём обращения** шлюз удаляет заголовки с учётными данными.
2. Узлы **Запрос к Яндексу** и **Яндекс после поиска** используют один Header Auth с заголовком `Authorization` и значением вида `Bearer <API-ключ>`. При восстановлении замените `REPLACE_FOLDER_ID` в узле **Подготовка запроса** и в заголовках `OpenAI-Project` обоих HTTP-узлов. [Yandex AI Studio](https://aistudio.yandex.ru/ru/docs/ai-studio/api-ref/authentication)
3. Узел **GigaChat — резервная модель, подключение запланировано** отключён. Для будущей активации потребуется отдельно настроить получение токена доступа и поддержку ответа GigaChat в FastAPI. При ошибке вебхука работает прямой маршрут к YandexGPT. [Авторизация GigaChat](https://developers.sber.ru/docs/ru/gigachat/api/reference/rest/gigachat-api)
4. Опубликуйте существующий workflow. Для FastAPI настройте адрес локального шлюза, режим `N8N_WEBHOOK_AUTH=basic` и пароль с ограниченным доступом. [Вебхук n8n](https://docs.n8n.io/integrations/builtin/core-nodes/n8n-nodes-base.webhook/)
5. Для проверки отправьте запрос через `POST /api/v1/chat`. Основной маршрут возвращает `provider: yandex` и выполненное действие `route_n8n`. При неверном пароле локальный шлюз возвращает HTTP 401.

HTTP-узлы моделей ограничены 7 секундами каждый. YandexGPT может выполнить один вызов каталога с таймаутом 3,5 секунды и запросить итоговый ответ. Общий лимит workflow — 26 секунд, таймаут адаптера — 27 секунд. При сбое webhook FastAPI пробует прямые вызовы из раздела ниже. Поле `provider` сообщает, откуда получен ответ. Контакты из формы заявки через webhook не передаются. Сообщение чата передаётся провайдерам, поэтому для проверки используйте сообщения без персональных данных. Хранение успешных, ошибочных и ручных запусков в экспортируемом workflow отключено.

## Прямое подключение для стенда

FastAPI вызывает YandexGPT напрямую через Responses API, если webhook не настроен или завершился ошибкой. Для прямого вызова сервис FastAPI получает `YANDEX_API_KEY` и `YANDEX_FOLDER_ID` из внешнего файла окружения, например через `EnvironmentFile` в systemd. Резервный узел GigaChat не участвует в обработке обращений.

Прямой вызов YandexGPT может один раз обратиться к локальному инструменту `search_catalog`. Функция ограничена пятью товарами и проверяет длину запроса. История действий возвращается через `actions`, без текста запроса и внутренних параметров. Workflow n8n использует предварительно подобранные карточки и при вызове `search_catalog` запрашивает до пяти товаров из API каталога.

Для проверки доступа и вызова инструмента запустите из корня проекта:

```bash
(
  set -a
  . "${SUPPORT_SECRETS_FILE:?Укажите путь к защищённому файлу окружения}"
  set +a
  python3 -m app.ai
)
```

Проверка выполняет два запроса с тестовым текстом и печатает только результат. Документация сценария доступна в [Yandex AI Studio](https://aistudio.yandex.ru/ru/docs/ai-studio/operations/agents/create-function-text-agent).

## Проверенный маршрут

В n8n 2.35.7 workflow импортирован и опубликован в отдельном тестовом
экземпляре на loopback. Реальный запрос `POST /api/v1/chat` прошёл через
webhook к YandexGPT. Неверный секрет вернул HTTP 403. В [предыдущем измерении](../docs/economics.md) один запрос к Text Generation дал 237 токенов. Текущая версия перешла на Responses API и возвращает `usage` последнего вызова.

### Рабочий экземпляр

Workflow `Support-to-Sale AI | Chat v1` с ID `iikuznitsaChat01` опубликован
в установленном n8n 2.46.6. FastAPI вызывает webhook через локальный шлюз.
Путь, секрет и режим авторизации читаются из отдельных файлов в `.stand/`.
При ошибке вебхука приложение пробует прямую интеграцию с YandexGPT. Если обе попытки не дали результата, FastAPI возвращает каталожный ответ. Автоматическое обращение возможно при действующей клиентской сессии и доступном лимите записей. Запросы с точным подтверждённым ответом обслуживает локальная база знаний.


### Локализация схемы

У 12 рабочих узлов есть русские названия и видимые на схеме Notes с назначением, входом, действием и выходом. Семь Sticky Notes поясняют общий маршрут, приём, работу модели, каталог, проверку, возврат клиенту и ошибки.

## Контракт шлюза

FastAPI передаёт `message`, до пяти предварительно подобранных `products`,
проверенные фрагменты `knowledge` и историю `history`. Workflow возвращает
`answer` и `provider`. После обращения к инструменту могут быть возвращены
`tool_status` и `products`. FastAPI заново проверяет карточки по каталогу.
Поле `usage` в webhook-ответе относится к последнему модельному вызову, а
не ко всему обращению. Клиентскому чату оно не передаётся.

[Резервная копия до локализации](backups/chat-v1-before-localization.json) получена из опубликованной версии. Ссылки на секреты в копии удалены, идентификатор каталога Яндекса заменён шаблоном. Для восстановления нужно привязать те же учётные данные к существующему workflow.
